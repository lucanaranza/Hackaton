\hypertarget{overview}{%
\section{Overview}\label{overview}}

The ephemerides pipeline answers the question the topography cannot:
\emph{from this point on the Moon, when are the Sun and the Earth above
the real terrain?} From that it derives illumination, solar energy and
direct-to-Earth communication, per cell and over time. Everything lives
in \texttt{Hackaton\_Ephemerids/}.

\textbf{Data flow}

\begin{enumerate}
\def\labelenumi{\arabic{enumi}.}
\tightlist
\item
  \texttt{site\_cells.csv} from the topography pipeline
  (100 m cells) gives the near terrain and the slope of each cell.
\item
  \texttt{LDEM\_60S\_240MPP\_ADJ} (240 m/px) gives the
  far terrain out to 200 km.
\item
  \texttt{mappatura.py} builds a grid of 500 m cells
  over the site, computes a 360° horizon for each cell, then evaluates
  Sun and Earth for each cell every hour for a year.
\item
  Results: a static map (yearly percentages) and a time evolution (one
  bit per cell per hour, for the web app's time slider).
\end{enumerate}

Using \texttt{MOON\_ME\_DE421} is what makes the
ephemerides and the LOLA DEMs share the same latitude/longitude: a
site's coordinates mean the same point in both pipelines.

\textbf{Example (Sito\_NPA,
\texttt{out\_v2/Sito\_NPA})}: 40 × 40 cells of 500 m
(20 × 20 km), year 2027, hourly. Light ranges 0--34.5 \% of the time
(mean 18.1 \%), useful communication 0--46.7 \%, light + communication
0--16.7 \%; longest continuous darkness at the best cell 573 h
(\textasciitilde24 days). Best landable cell: −87.0504°, −74.6045°, 5.0°
mean slope.

Conventions (identical to the topography pipeline): times UTC ISO 8601;
angles in degrees; azimuth from north (0°) towards east (90°); latitude
positive north, longitude positive east; Moon as a sphere of R = 1 737
400 m.

\hypertarget{how-the-pipeline-runs-step-by-step}{%
\section{How the pipeline runs: step by
step}\label{how-the-pipeline-runs-step-by-step}}

\begin{enumerate}
\def\labelenumi{\arabic{enumi}.}
\tightlist
\item
  \texttt{mappatura.py} reads the topography cells from
  a path given on the command line (\texttt{--celle}):
  the CSV stays in the topography folder, no copy is kept in the
  ephemerides folder.
\item
  It uses the functions of \texttt{effemeridi.py}
  (kernel loading, solar-disk fraction, constants) for the ephemeris
  calculation.
\item
  The ephemerides come from JPL (DE421 and the lunar orientation
  kernels), stored in \texttt{dati\_effemeridi/} and
  valid until 2050.
\item
  For every cell it computes the terrain obstruction (its own 360°
  horizon, near + far DEM) and compares it with the elevation and
  azimuth of the Sun and the Earth.
\item
  It computes illumination, energy and communication in two ways, both
  with a 1 h time step over one year:

  \begin{itemize}
  \tightlist
  \item
    \textbf{static} (\texttt{mappa\_*.json}): no time
    series is stored; every quantity is reduced to a yearly percentage
    or maximum per cell;
  \item
    \textbf{dynamic} (\texttt{evoluzione\_*.json}): a
    boolean array of size \emph{n\_instants × n\_cells} (grid rows ×
    columns flattened), preallocated with zeros and filled time step by
    time step, then packed into bits.
  \end{itemize}
\item
  Results are saved in one sub-folder per site in
  \texttt{out\_v2/}.
\end{enumerate}

Command used for all sites (PowerShell, from
\texttt{Hackaton\_Ephemerids}):

\begin{lstlisting}
Get-ChildItem "$topo\risultati_v2" -Directory | ForEach-Object {
  $csv = Join-Path $_.FullName "site_cells.csv"
  if (Test-Path $csv) {
    $nome = $_.Name.Substring(0,1).ToUpper() + $_.Name.Substring(1)
    Write-Host "== $nome"
    .\.venv\Scripts\python.exe mappatura.py --celle $csv --far $far --nome $nome `
        --uscita "out_v2\$nome" --passo-tempo 60 --passo-evoluzione 60 }
}
\end{lstlisting}

\texttt{\$topo} is the topography results root and
\texttt{\$far} the regional LDEM. Since
\texttt{--passo} is not given, cells are 500 m;
\texttt{--inizio} and
\texttt{--giorni} keep their defaults (2027-01-01, 365
days).

\hypertarget{helpers-76151}{%
\subsection{Helpers (76--151)}\label{helpers-76151}}

\textbf{\texttt{\_maschera(orizzonte, azimut)}
(76--82)} --- horizon elevation in the direction of the Sun or Earth.

\begin{itemize}
\tightlist
\item
  \textbf{78--79} No horizon → flat sphere, 0° everywhere.
\item
  \textbf{81} Azimuths 0, 1, \ldots, 359° for the 360 horizon values.
\item
  \textbf{82} \texttt{np.interp(..., period=360)}:
  linear interpolation that wraps around 360° → 0°.
\end{itemize}

\textbf{\texttt{\_trova\_eventi(tempi, margine, ...)}
(85--98)} --- finds rise/set events.

\begin{itemize}
\tightlist
\item
  \textbf{91--93} Scans consecutive samples of the margin (elevation −
  horizon) for a sign change.
\item
  \textbf{94--95} Linear interpolation of the zero crossing: fraction
  \texttt{a/(a−b)} of the interval. With a 10 min step
  the error is a few minutes.
\item
  \textbf{96} Rising if the margin increases, setting otherwise.
\end{itemize}

\textbf{\texttt{\_ore} (101--103)}: hours = number of
\texttt{True} samples × step / 60.
\textbf{\texttt{\_durata\_testo} (106--113)}: timedelta
→ \texttt{"4g 7h 12m"} (days, hours, minutes).
\textbf{\texttt{\_iso} (116--118)}: ISO 8601 UTC string
with \texttt{Z}, readable by JavaScript
\texttt{Date}.

\textbf{\texttt{\_frazione\_disco(u)} (121--130)} ---
visible fraction of the solar disk.

\begin{lstlisting}[language=Python]
129      u = np.clip(u, -1.0, 1.0)
130      return 1.0 - (np.arccos(u) - u * np.sqrt(1.0 - u * u)) / np.pi
\end{lstlisting}

\begin{itemize}
\tightlist
\item
  \texttt{u} = (centre elevation − horizon) / apparent
  radius. The hidden part is a circular segment of area (arccos u −
  $u\sqrt{1-u^2}$)·r²; dividing by πr² gives the hidden fraction. So u = −1 → 0
  (hidden), u = 0 → ½, u = 1 → 1 (fully visible). The terrain is assumed
  locally straight across the disk's width (\textasciitilde0.5°).
\end{itemize}

\textbf{\texttt{\_sequenza\_piu\_lunga} (133--151)} ---
longest run of consecutive \texttt{True} samples
(e.g.~continuous darkness) in hours, plus a flag that is
\texttt{True} if that run touches the start or end of
the period (the real duration may then be longer).

\begin{itemize}
\tightlist

  \textbf{171--172} A naive datetime is taken as UTC.
\item
  \textbf{173--175} \texttt{n} instants including both
  ends; one vectorised Skyfield \texttt{Time} array.
\item
  \textbf{177} The observer: the Moon's centre plus a point on the lunar
  surface at (lat, lon) in \texttt{MOON\_ME\_DE421}.
  Height 0, i.e.~on the reference sphere.
\item
  \textbf{178} Observer position at all instants.
\item

  \begin{itemize}

\item

\hypertarget{issues-found-in-the-ephemerides-code}{%
\section{Issues found in the ephemerides
code}\label{issues-found-in-the-ephemerides-code}}

Overall the physics is right: true lunar orientation with librations,
light time and aberration, parallax, partial solar disk, and a frame
consistent with LOLA. The weak points are modelling scope and the
coupling with the topography outputs.

\hypertarget{affects-results}{%
\subsection{Affects results}\label{affects-results}}

\textbf{1. \texttt{mappatura.py} computes its own
horizon from 100 m mean elevations, not from the topography
\texttt{horizon.json}.}

\begin{itemize}
\tightlist
\item
  In \texttt{--celle} mode the near terrain is the 100
  m cell-mean grid, sampled every 10 m. Small rims, boulders and slopes
  inside a 100 m cell are averaged out, and the observer stands 2 m
  above a 100 m mean, not above the real ground. The docstring itself
  says the CSV mode is slightly optimistic.
\item
  On the positive side, this means the topography coordinate issue
  (horizons at the DEM centre) does \textbf{not} affect the maps: each
  500 m cell has its own horizon.
\item
  The two horizon codes differ (straight rays in the map plane vs
  geodesics; 10/240 m steps vs 5/100 m).
  \texttt{--confronta} exists to quantify this, but its
  result isn't stored in the outputs.
\end{itemize}

\textbf{2. Lunar eclipses are not modelled.} Light only checks the
terrain. When the Earth passes in front of the Sun (a lunar eclipse seen
from Earth, \textasciitilde2 per year, up to \textasciitilde3--5 h each
including penumbra), the Sun counts as visible and producing full power.
For survival of the darkest period this matters: an eclipse can extend a
dark period or occur while batteries are low.

\textbf{3. Direct-to-Earth link = Earth above the terrain by 0.5°.}
Ground-station visibility (DSN antennas rotating with the Earth),
Earth's disk size (\textasciitilde0.95° radius) and link budget are not
modelled. \texttt{comunicazione\_pct} is an upper bound
on contact time.

\textbf{4. Power model.} The panel always points at the Sun, so no
cosine losses; the \textasciitilde±3.4 \% yearly solar-flux variation
(Earth--Sun distance) and panel temperature are ignored.
\texttt{energia\_pct} is a relative geometric index,
not a power budget.

\textbf{5. Missing terrain counts as no obstruction.}
\texttt{orizzonte\_celle} line 162 replaces NaN angles
with −90°. Unlike the topography pipeline, coverage is not reported per
cell, so a gap in the far DEM silently makes a cell look better lit.

\hypertarget{minor-or-cosmetic}{%
\subsection{Minor or cosmetic}\label{minor-or-cosmetic}}

\begin{itemize}
\tightlist
\item
  \textbf{6. Straight rays in the projection plane.} The docstring
  states \textless{} 0.4 \% scale error. With true scale at the pole the
  scale factor is k = 1 + ρ²/(4R²); at ρ ≈ 290 km (a site
  \textasciitilde90 km from the pole plus 200 km) k ≈ 1.007, so up to
  \textasciitilde0.7 \% --- still small for horizon angles, but the
  comment understates it.
\item
  \textbf{7. Duplicate ephemeris work.} With
  \texttt{--passo-tempo 60 --passo-evoluzione 60} (the
  command used) the Sun/Earth vectors and per-cell elevations are
  computed twice at identical steps.
\item
  \textbf{8. \texttt{margine\_bordo} in
  \texttt{mappa\_sito}} is never exposed on the command
  line; \texttt{ipotesi} in the JSON hard-codes 2 m, 10
  km and 200 km instead of reading the values actually used.
\item
  \textbf{9. \texttt{test\_luna.py} has no assertion.}
  Turning the 0.5° comparison into an \texttt{assert}
  would make it a real regression test.
\item
  \textbf{10. Event times in \texttt{effemeridi.py}}
  come from linear interpolation of the margin; with the 60 min step
  used for maps (vs 10 min default) errors grow to tens of minutes. The
  maps don't use events, so this only affects
  \texttt{valuta\_sito} with large steps.
\item
  \textbf{11. Dust risk thresholds} are team-chosen, and the code says
  so; treat the label as qualitative.
\item
  \textbf{12. \texttt{riepilogo\_mappe.csv/json}} have
  no generating script in the folder; how they were produced isn't
  reproducible from the repository.
\end{itemize}

\hypertarget{verified-correct}{%
\subsection{Verified correct}\label{verified-correct}}

\begin{itemize}
\tightlist
\item
  \texttt{MOON\_ME\_DE421} built from DE421 + PA
  kernels: same frame and longitudes as LOLA.
\item
  Light time, aberration and parallax included; refraction correctly
  absent.
\item
  Map-plane north = radial direction from the pole, east = 90°
  clockwise; azimuth from north towards east everywhere (Python and JS).
\item
  Horizon interpolation wraps at 360°.
\item
  Solar disk fraction formula (circular segment) and its limits.
\item
  Vector (not angle) interpolation in the web table; same
  elevation/azimuth maths in Python and JavaScript.
\item
  NaN → \texttt{null} in JSON; bit ordering of the
  evolution file documented in the file itself.
\end{itemize}
